## §1 Computational basis

Added hypothesis-style property tests over arbitrary modules and bundles generated by a new `valid_module_strategy`. The strategy constructs small but non-trivial modules (≤6 clauses, ≤4 templates + a catch-all if needed) that pass the validation harness by construction. Hypothesis discovers counterexamples by shrinking — fast inner loop matters more than input diversity at this scope.

## §2 Results

- **All 11 property tests pass** at hypothesis default settings. Test count: 97 → 108.
- **First `:verified` entries in the spec.** Pre-v0.13.0 the spec had zero `:verified` entries; post-v0.13.0 it has six.
- **OQ-002 closure** — the only `:argued` entry where mechanical verification was achievable now `:verified`. Remaining `:argued` entries are honest-effort items (manual-by-nature licensing, adopter-org-gated substrate enforcement, SOP-bound architecture decisions).
- **OQ-001 invariant** is now property-tested across arbitrary inputs, not just the medical-devices smoke fixture. Genuinely strengthens the load-bearing claim of the project.
- **Resolver purity** (OQ-010) verified via two properties: determinism + standards-monotonicity. The composition of these two captures most of what "pure function" means at the test surface; for full `:proved` would need either `mypy --strict` in CI or a port to a language with checked types.
- **Composition algebra** (OQ-011) verified via four properties: identity, idempotence-on-content, disjoint-union, conflict-raise. The algebraic surface of compose is now mechanically checked.
- **No false positives.** Hypothesis ran ~1100 total examples across the 11 properties without finding any counterexamples. The strategy is conservative (small modules) by design — for adversarial-input testing, the strategy bounds could be relaxed.

**Path to `:proved`:** the load-bearing invariants (OQ-001, OQ-002, OQ-010) are now property-tested across arbitrary inputs. Upgrade to `:proved` requires one of: (a) `mypy --strict` in CI plus type-level encoding of the invariant in the dataclass schema; (b) algebraic / mechanized proof in a theorem prover (Lean / Coq / Isabelle); (c) a port of the resolver to a language with checked types where the invariant becomes a type-level property. All three are substantial undertakings; none are on the immediate roadmap.

**Remaining `:argued` (7, all honest-effort):** OQ-003 (honesty bound — manual by nature), OQ-022 + OQ-023 (substrate enforcement gated on adopter-org configuration), OQ-062 (PHI/PII architecture SOP-bound), OQ-067 (forward-language not script — closed via doc fix), OQ-070 + OQ-071 (licensing claims — manual by nature).

This closure removes the last mechanically-upgradable `:argued` entry; future mechanical-evidence upgrades require structural moves (typecheck CI, theorem prover, etc.) rather than additional property tests.
