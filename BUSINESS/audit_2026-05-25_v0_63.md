## Notes for the next audit

- **Per-release scope-cell update discipline.** This audit's 3 findings (F-A / F-B / F-C) all trace to a single root cause: scope-table cells in README + catalog were not updated alongside per-release count changes. The dashboard "Latest" + ENGINE_SPEC status table + changelog WERE updated consistently. Adding "update README + catalog scope cells" to the per-release CLAUDE.md checklist would prevent recurrence; for now this audit handles the backlog.
- **CLI subcommand cell discipline.** Same pattern but already up-to-date — the README v0.62 change correctly bumped `Engine CLI subcommands` from 9 → 10 when `verify-deployment` shipped. So per-release version-cell updates ARE happening; only the scope-aggregate counts (spec entries, templates) were missed.
- **Architecture-tier entries are now 8** (OQ-012 + OQ-014 + OQ-115 + OQ-116 + OQ-117 + OQ-122 + OQ-124 + OQ-126). Pattern: every Architecture-tier addition since OQ-115 has been a new CLI surface (coverage + crosswalk + jurisdictions-query + template_schema CI gate + doc_control workflow + verify-deployment). Future Architecture-tier additions likely follow the same shape.
- **Spec entry density** now ~96% of module count (111 entries / 116 modules); the remaining ~4% are bookkeeping rollups (OQ-118 batches 4 modules + OQ-120 batches 6 priorities + OQ-121 batches 5+5 + OQ-125 batches 4 presets — each by intent).
- **Forward-work remaining**: 2 hard priorities (P2 + P15). The first realistic schedule for P2 is when adopter feedback escalates from "would be nice" to "blocked on this." P15 is the strategic differentiator but the multi-session scope means it needs a dedicated arc.
