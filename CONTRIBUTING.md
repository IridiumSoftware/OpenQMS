# Contributing to Open QMS

We welcome contributions from quality professionals, regulatory specialists, software engineers, and anyone who has dealt with the pain of traditional QMS platforms.

## How to contribute

1. **Report issues.** Found a gap in the regulatory mapping? A workflow that doesn't handle an edge case? Open an issue.
2. **Submit regulatory modules.** If you work in pharma, aerospace, automotive, or food safety, we'd love help building regulatory modules for those industries.
3. **Improve CI workflows.** The enforcement layer is the core product. Better traceability checks, smarter training triggers, and more robust release gates are always welcome.
4. **Write documentation.** Guides for auditors, setup walkthroughs, and validation protocol templates are high-impact contributions.
5. **Fix bugs.** Standard open-source process: fork, branch, fix, PR.

## Process

1. Fork the repo
2. Create a feature branch (`git checkout -b feature/your-feature`)
3. Make your changes
4. Ensure any new workflows pass locally (use `act` for local GitHub Actions testing)
5. Open a PR with a clear description of what the change does and why

## Code of conduct

Be professional. This project exists to help organizations build safer products. Treat contributors with the same rigor and respect you'd want in a quality system.

## Regulatory contributions

If you're contributing regulatory mappings or compliance guidance:
- Cite the specific clause/section of the standard or regulation
- Distinguish between requirements (shall), recommendations (should), and your interpretation
- Flag jurisdiction-specific requirements (FDA vs EU vs Health Canada, etc.)
- Do not copy copyrighted standard text verbatim; paraphrase and cite
