# Integrated Management System (IMS) — Open QMS cross-overlay

**Cross-overlay.** Binds multiple Annex SL management systems (quality + environmental + OH&S + energy + IS + others) into a single coordinated IMS.

## Scope

Organisations operating multiple ISO management systems wanting to coordinate them via Annex SL shared high-level structure rather than maintaining parallel siloed systems.

## Standards covered

8 clauses covering integration patterns:
- Annex SL shared HLS leverage
- Shared policy + objectives
- Shared context + interested-parties analysis
- Integrated risk + opportunity register
- Combined management review (single meeting covering all MS inputs)
- Combined audit programme per ISO 19011:2018
- Integrated documented-information control
- Annex SL HLS version-tracking + coordinated transitions

## Composition

`integrated-management-system + iso-9001-bearing-vertical + iso-14001 + iso-45001 + iso-50001 + iso-27001` (typical full IMS scope).

Per-vertical example — full IMS pharma manufacturer:
- `pharma + iso-27001 + iso-14001 + iso-45001 + iso-50001 + integrated-management-system`

Per-vertical example — chemicals full IMS:
- `chemicals + iso-27001 + iso-14001 + iso-45001 + iso-50001 + iso-31000 + integrated-management-system`

May compose with `iso-31000` meta-framework overlay for integrated risk methodology.

## Module shape

This is a **cross-overlay** — binds across multiple cross-cutting overlays (not just verticals). Distinct from cross-cutting (single dimension) and sub-overlays (within-overlay tier).

## When to use

- Organisations operating ≥3 ISO management systems with shared infrastructure
- Pursuing combined IMS certification (multi-MS audit day-rate reduction)
- Want single management review covering all MS scopes
- Have integrated risk register desire (vs. siloed per-MS risk treatments)
- Mature compliance programs ready to consolidate

## When NOT to use

- Operating only 1-2 management systems (overhead not yet justified)
- Per-MS certification bodies + audit cadences locked-in long-term separately
- Specific regulatory requirement to maintain siloed MS-per-domain (rare)
